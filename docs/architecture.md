# Runtime architecture

## AV1 factory order

The patched AV1 callback preserves Resolve's existing behavior and inserts the private FFmpeg route at the generic FFmpeg factory boundary:

1. NVIDIA factory, unless `Local.IO.SoftwareAV1Decode` is exactly `"1"`.
2. Resolve's generic FFmpeg decoder factory, with `av01 -> AV_CODEC_ID_AV1 (226)` registered in its private FourCC map. The provider selects Intel QSV when available, otherwise private FFmpeg/libdav1d.
3. Resolve's AOM factory only when the custom factory returns no decoder object.

A decoder that was successfully created but later fails to open or decode is not silently retried through AOM. This keeps factory unavailability distinct from stream/decode errors.

## Provider boundary

The runtime wraps the generic FFmpeg calls used by the Resolve factory:

- `avcodec_find_decoder`
- `avcodec_alloc_context3`
- `avcodec_open2`
- `avcodec_close`
- `avcodec_free_context`
- `avcodec_send_packet`
- `avcodec_receive_frame`
- `avcodec_flush_buffers`

An ownership registry identifies contexts allocated for the private AV1 codec. Calls for all other codec contexts are forwarded to Resolve's original FFmpeg implementation. The registry also coordinates close/free with active provider operations.

The private FFmpeg pair is loaded into the base linker namespace with `RTLD_LOCAL | RTLD_DEEPBIND`. Their ELF SONAMEs are renamed to `libdavinci_avutil.so.58` and `libdavinci_avcodec.so.60`, and private libavcodec depends on the matching private util SONAME through an `$ORIGIN` RUNPATH. This prevents collision with Resolve's same-version libraries while allowing oneVPL to load the Intel VA driver plugin. The provider discovers exactly one accessible Intel render node by PCI vendor ID; if QSV device creation succeeds, it selects `av1_qsv`. Otherwise it selects `libdav1d`. Resolve's `Local.IO.SoftwareAV1Decode="1"` setting explicitly selects libdav1d and bypasses QSV as well as NVIDIA. QSV hardware frames are transferred to private system-memory NV12/P010 frames, then copied into Resolve-owned frame objects at the provider boundary. Non-AV1 contexts continue to use Resolve's original FFmpeg implementation.

## Live transaction

The installer validates the Resolve executable fingerprint, target mapping identity, callback bytes, map structure, allocator/rebalancer targets, and all patch instructions before writing. It then:

1. Prepares the Resolve-owned map node before the all-stop window.
2. Allocates a relay page and publishes wrapper jump stubs.
3. Patches ten generic FFmpeg CALL sites and inserts `av01 -> 226` into the existing red-black tree.
4. Publishes the callback detour last with an aligned atomic instruction write.
5. Synchronizes instruction streams and restores original executable-page protections.

The transaction has explicit rollback and failure-injection tests. A failed validation does not partially install the patch. The controller also checks that its runtime, bootstrap, and private FFmpeg artifacts match the hashes generated by the local build.

## Process and allocator safety

- The transaction is performed at the validated pre-main stop with one target thread.
- The Resolve map allocator must not be called while every target thread is stopped: Resolve's TBB allocator has internal locks that can be held by a suspended thread. The map node is allocated before the all-stop phase and released only after the process resumes.
- Resolve-owned and private-FFmpeg-owned allocations must be freed by their original allocator. In particular, the generic factory's `extradata` is allocated by Resolve's libavutil and is rehomed into private libavutil before private `avcodec_open2`.
- The installer changes only the live process. It does not patch files under `/opt/resolve`.

## Supported target

Addresses and structure layouts are specific to Resolve 21.1.1.0010 on Linux x86-64. They are not portable constants. The installer checks the target fingerprint and refuses unknown builds.
